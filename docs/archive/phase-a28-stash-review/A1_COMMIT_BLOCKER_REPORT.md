## 4. Recommended git strategy

Given the above, cleanly committing "Sprint A1 only" is not achievable without one of:

1. **First land the backlog itself, as its own properly attributed commit(s) — not A1's.** The
   cleanest sequencing: commit Sprint 4.7 (Orders checkout lifecycle) as its own commit citing
   `SPRINT_4_7_ORDERS_CORE_REPORT.md`, then the Admin-wiring/HTTP-surface backlog as one or more
   further commits citing their own sprint reports (the multi-context admin surface likely needs
   more than one commit given its size and the number of distinct sprints bundled into
   `admin-routes.ts`/`composition.ts`), _then_ Sprint A1 becomes a small, genuinely isolable commit
   on top, the same shape as A0. This is real, separately-scoped work (auditing and re-verifying
   each backlogged sprint's content against its own report, the way A0 did for its own scope) —
   not something to fold into A1 silently.
2. **Leave Sprint A1 uncommitted**, same as the backlog it depends on — consistent with this
   repo's dominant pattern to date, but means A1 has no commit/tag of its own until (1) happens.
3. **A deliberate, explicitly-scoped exception**: commit the backlog and A1 together in one
   pass, accepting that it will not satisfy "no unrelated staging" / "no broad commits" — only if
   the user decides that rule should be waived for this specific situation.

This report does not choose between them — that choice, and any resulting `git add`/`git commit`,
is intentionally left to the user's direction, per their explicit stop instruction.
