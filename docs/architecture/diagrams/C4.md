# C4 Architecture Diagrams

> H-5 production-readiness view. C4 levels 1–3 for the Morbeh platform, rendered as Mermaid. These
> summarise the architecture the 15 architecture docs + ADRs define — they do not introduce new
> structure. Context: one runtime image (`api`/`worker`/`scheduler`) composes the bounded-context
> modules over shared infrastructure.

## Level 1 — System Context

```mermaid
C4Context
  title Morbeh Commerce OS — System Context
  Person(admin, "Merchant / Operator", "Manages catalog, orders, tenants via the admin UI")
  Person(shopper, "Shopper", "Browses & buys via the storefront")
  System(morbeh, "Morbeh Platform", "Multi-tenant commerce + experience OS (39 bounded-context modules)")
  System_Ext(ory, "Ory (Hydra/Kratos/Keto)", "OIDC issuer, identity, authorization (ReBAC)")
  System_Ext(kms, "KMS / Vault", "Envelope-encryption KEK, secrets")
  System_Ext(psp, "Payment Providers", "Charge/refund via the Payments provider port")
  System_Ext(carrier, "Carriers", "Labels & tracking via the Shipping port")
  Rel(shopper, morbeh, "Shops", "HTTPS/JSON")
  Rel(admin, morbeh, "Operates", "HTTPS/JSON")
  Rel(morbeh, ory, "AuthN/Z", "OIDC / REST")
  Rel(morbeh, kms, "Wrap/unwrap keys, fetch secrets")
  Rel(morbeh, psp, "Payments", "provider port")
  Rel(morbeh, carrier, "Fulfillment", "carrier port")
```

## Level 2 — Containers

```mermaid
C4Container
  title Morbeh Platform — Containers
  Person(client, "Client", "Storefront / Admin")
  System_Boundary(morbeh, "Morbeh Platform") {
    Container(api, "runtime-api", "Node 22 / tsx", "HTTP transport for /api + /healthz /readyz /metrics")
    Container(worker, "runtime-worker", "Node 22 / tsx", "Kafka/Redpanda consumers, at-least-once + inbox dedupe")
    Container(scheduler, "runtime-scheduler", "Node 22 / tsx", "Singleton periodic jobs (Redis lock)")
    ContainerDb(pg, "PostgreSQL", "Postgres 16", "System of record + transactional outbox (CDC)")
    ContainerDb(redis, "Redis", "Redis 7", "Cache, locks, rate state")
    ContainerQueue(rp, "Redpanda", "Kafka API", "Event backbone")
    ContainerDb(ch, "ClickHouse", "OLAP", "Analytics read models")
  }
  System_Ext(ory, "Ory", "AuthN/Z")
  Rel(client, api, "REST", "HTTPS")
  Rel(api, pg, "read/write", "SQL")
  Rel(api, redis, "cache/locks")
  Rel(api, ory, "verify token / authorize")
  Rel(pg, rp, "outbox → CDC (Debezium)")
  Rel(rp, worker, "consume events")
  Rel(worker, pg, "read/write projections")
  Rel(worker, ch, "materialize analytics")
  Rel(scheduler, pg, "enqueue periodic work")
```

## Level 3 — Runtime module composition (Component)

```mermaid
C4Component
  title runtime-api — Component (module kernel)
  Container_Boundary(api, "runtime-api") {
    Component(http, "HTTP transport", "@platform/http", "Routing, security headers sink, metrics sink")
    Component(kernel, "Module kernel", "runtime/modules", "Wires bounded-context modules, start/stop lifecycle (F4)")
    Component(edge, "Edge zero-trust guard", "security/edge", "EvaluateAccess reuse, policy cache")
    Component(ctx, "Bounded-context modules", "services/*", "identity, catalog, orders, payments, security, … (39)")
    Component(health, "Health/metrics", "runtime/health", "/healthz /readyz /metrics (F5)")
  }
  Rel(http, edge, "authorize request")
  Rel(edge, ctx, "delegated use-cases")
  Rel(kernel, ctx, "compose + lifecycle")
  Rel(kernel, health, "readiness aggregation")
```
