# WP-10 — guard verification (definition-of-done pass, 2026-09-26)

Method: for each guard, the guard was removed or inverted in the working tree, the tenant test suites of
every package that could catch it were run, the failing tests were recorded, and the file was restored
(the tree was verified to contain only intended edits afterwards). Nothing was mutated in a committed
state. 157 mutations; **145 in the first pass, 31 of which survived** (removal turned nothing red: 26 across the T10.5–T10.7 guards, plus all 5 sampled Prisma repositories). The
survivors are reported first-class below, not folded into a total. Rows marked `new guard` are guards added
by this pass, mutated the same way after they were written.

**Reading the table.** `red N` = N tests failed with the guard removed. `SURVIVED; after: red N` = nothing failed
on the first pass; N is the count after the test/fix in this pass. Equivalent/redundant survivors are named
as such (K02/K03, S02, G01) and are not counted as gaps.

**What this does not show.** A mutation that turns a test red shows the test can fail, not that the guard is
sufficient. Postgres was not touched: every Prisma branch was exercised only through `createFakePrisma`
(where applied literally) or through the static `where` check. The mutations cover the guards named in the
brief and the ones found while reading; ~50 Prisma repositories' individual `where` clauses were covered by
the static check (PG1) plus 5 sampled mutations (PR1–PR5), not one mutation each.
