## Shared vocabulary (Task 1 produces, Tasks 2-3 consume)

```ts
// services/security/src/domain/staff.ts
export type StaffRole = "admin" | "operator" | "viewer";
export const STAFF_ROLES: readonly StaffRole[] = ["admin", "operator", "viewer"];
export const OWNER_ROLE_KEY = "platform-admin";
export type StaffStatus = "active" | "invited" | "invitation_expired" | "deactivated";
export interface StaffMemberView {
  readonly principalExternalId: string;
  readonly email: string; // credential identifier without the "staff:" prefix
  readonly role: StaffRole | "owner"; // "owner" = holds platform-admin (wins over any other key)
  readonly status: StaffStatus;
  readonly isOwner: boolean;
  readonly isSelf: boolean; // principalExternalId === actor
  readonly addedAt: string; // principal createdAt ISO
  readonly lastSignInAt: string | null; // max(security.sessions.established_at) for the principal
  readonly invitation: {
    readonly id: string;
    readonly expiresAt: string;
    readonly version: number;
  } | null; // pending (incl. expired) only
}
```

Status rule (in this order): a pending invitation whose `expiresAt > now` → `invited`; a pending invitation with `expiresAt <= now` → `invitation_expired`; principal `suspended` → `deactivated`; otherwise `active`. Role rule: holds `platform-admin` → `owner`; else the highest active staff role key by rank admin > operator > viewer; a staff credential with no mapped role is listed with role `viewer` only if it holds `viewer`, otherwise it is omitted (not a staff member).
